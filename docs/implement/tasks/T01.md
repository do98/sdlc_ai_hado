## 1. Mục tiêu

Có một kho mã chạy được trên máy mọi thành viên và trên CI, với luật ranh giới module được máy kiểm tra, để mọi task sau có chỗ đặt mã thống nhất và không vi phạm quy tắc kiến trúc của kế hoạch (§6).

## 2. Phạm vi

**Làm:** cấu trúc monorepo, công cụ build/lint/test cho FE và BE, luật ranh giới R-1…R-6, CI, README chạy nhanh, quy ước nhánh/commit.

**Không làm:** logic nghiệp vụ; design tokens và component (T02); khung backend và migration (T03).

## 3. Các bước thực hiện

| # | Việc | Đầu ra kiểm tra được |
|---|---|---|
| a | Tạo monorepo `apps/web` (Vue 3 + TypeScript + Vite) và `apps/api` (Java 21 + Spring Boot 3, Maven) | `npm run build` và `mvn -q verify` chạy xanh trên khung rỗng |
| b | Thêm ESLint + Prettier + `vue-tsc` cho FE; Checkstyle/Spotless (hoặc tương đương) cho BE | `npm run lint`, `mvn spotless:check` xanh |
| c | Cài luật ranh giới module FE (`eslint-plugin-boundaries` hoặc `dependency-cruiser`) theo R-1…R-6 của SDD; luật BE bằng ArchUnit | Thêm một import vi phạm thử → lint/test đỏ; bỏ đi → xanh |
| d | Luật cứng ghi trong cấu hình lint: `fetch`/`XMLHttpRequest` chỉ được dùng trong `shared/api`; HTML từ LLM chỉ render qua `shared/lib/markdown`; cấm `localStorage`/`sessionStorage` cho token | Test lint cho từng luật (tệp mẫu vi phạm phải bị báo lỗi) |
| e | CI (nền tảng CI của đội) chạy: lint, test đơn vị FE (Vitest), test BE (JUnit 5), build ảnh/artefact | Pipeline xanh trên PR mẫu; thời gian ≤ 10 phút `[Đề xuất]` |
| f | Bảo vệ nhánh chính: bắt buộc CI xanh và ≥ 1 review | Cấu hình được kiểm tra bằng PR thử |
| g | `README.md` gốc: cách cài, chạy, test trong ≤ 15 dòng; `CONTRIBUTING.md` (nhánh `feat/<task>-<mô-tả>`, commit, review) | Người mới chạy được theo README |

## 4. Đặc tả kỹ thuật

- Cấu trúc thư mục FE (theo SDD): `src/app`, `src/shared/{ui,api,lib}`, `src/features/*`. Luật ranh giới cụ thể R-1…R-6 **lấy từ SDD §1.2**; nếu SDD chưa có tệp trong repo thì dùng bộ luật tối thiểu dưới đây `[Đề xuất]` và đối chiếu sau:
  1. `shared` không import từ `features` hay `app`.
  2. `features/<A>` không import từ `features/<B>`; dùng qua `shared` hoặc `app`.
  3. Chỉ `shared/api` được gọi mạng.
  4. Chỉ `shared/lib/markdown` được tạo HTML từ chuỗi.
  5. `app` là nơi duy nhất ghép các feature.
  6. Component không import trực tiếp thư viện HTTP.
- BE: gói `api` (controller), `service`, `repository`, `domain`, `integration` (LLM, PDF). ArchUnit: `controller` không gọi `repository` trực tiếp; `domain` không phụ thuộc Spring.
- Phiên bản công cụ ghi cố định (`.nvmrc`, `.sdkmanrc`/toolchain Maven).

## 5. Tiêu chí hoàn thành

- [ ] Clone mới + làm theo README chạy được FE dev server và BE.
- [ ] CI xanh trên nhánh chính; PR có lint vi phạm bị chặn.
- [ ] Bảy luật (R-1…R-6 + luật token) đều có test chứng minh bị bắt khi vi phạm.

## 6. Kiểm thử

Test cấu hình lint (tệp vi phạm mẫu trong `tools/lint-fixtures/`), test ArchUnit, và một PR thử có từng loại vi phạm.

## 7. Rủi ro và câu hỏi mở

- Chọn công nghệ BE thuộc việc chốt #1 (T06); nếu đổi khỏi Java, thay phần `apps/api` nhưng giữ nguyên luật FE và CI.
- Nền tảng CI chưa nêu trong kế hoạch: dùng nền tảng sẵn có của đội, ghi vào README.

## 8. Định nghĩa hoàn thành (DoD) chung

- [ ] Mã được review bởi ≥ 1 người khác tác giả; CI xanh (lint gồm luật ranh giới module, test, build).
- [ ] Mọi mục trong "Tiêu chí hoàn thành" ở trên đã đạt và có bằng chứng (test, báo cáo hoặc ảnh chụp).
- [ ] Không ghi nội dung câu hỏi/câu trả lời/văn bản tài liệu vào log; không lưu token ở `localStorage`; nội dung LLM chỉ render qua `shared/lib/markdown`.
- [ ] Hợp đồng API (OpenAPI/SSE ở T05) và tài liệu liên quan được cập nhật nếu thay đổi.
- [ ] Dùng được bằng bàn phím và có thông báo trợ năng phù hợp (với task giao diện).

## 9. Ghi chú về nguồn và mức chắc chắn

Kế hoạch tham chiếu các mã định danh nằm trong tài liệu chưa có trong repo (SDD UI/UX: `IF-0x`, `ALG-0x`, `ST-0x`, quy tắc `R-1…R-6`; user stories: `AC-012.x`, `AC-024.2`, `US-0xx`, `EV-0xx`, `T1…T11`; yêu cầu: `TH-0x`, `MET-002`, `G-xx`, `DEP-002`). Task này chỉ dùng các chi tiết **có trong kế hoạch**; chi tiết bổ sung được gắn `[Đề xuất]` và phải đối chiếu với tài liệu gốc khi có, trước khi coi là nghiệm thu.
