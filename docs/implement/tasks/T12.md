## 1. Mục tiêu

Cho một câu hỏi, trả về các đoạn liên quan nhất từ **mọi** tài liệu `READY` trong workspace (không giới hạn một tài liệu), kèm điểm tương đồng, để T13 đưa vào prompt và dựng trích dẫn.

## 2. Phạm vi

**Làm:** vector hóa câu hỏi, truy vấn pgvector top-k trên tài liệu sẵn sàng, ngưỡng tối thiểu, cấu hình `k`, trả đoạn kèm metadata (tài liệu, trang, offset).

**Không làm:** gọi LLM sinh câu trả lời (T13); tìm toàn văn/hybrid (kế hoạch chỉ nêu vector; nếu T21 cho thấy cần, thêm sau).

## 3. Các bước thực hiện

| # | Việc | Đầu ra kiểm tra được |
|---|---|---|
| a | Interface `Retriever.retrieve(query, k) -> List<RetrievedChunk>`; `RetrievedChunk{chunkId, documentId, documentName, page, charStart, charEnd, content, score}` | Chữ ký ổn định cho T13 |
| b | Embedding câu hỏi qua `EmbeddingClient` (cùng mô hình với lúc lập chỉ mục; lưu `embedding_model` để phát hiện lệch) | Test: dùng bản giả xác định |
| c | Truy vấn: `SELECT … FROM chunks c JOIN documents d ON d.id=c.document_id WHERE d.status='READY' ORDER BY c.embedding <=> :q LIMIT :k` (cosine); `k` mặc định 8 `[Đề xuất; tinh chỉnh ở T21]` | Test: tài liệu `ERROR/PROCESSING/DELETED` không bao giờ xuất hiện |
| d | Điểm = `1 - cosine_distance`; bỏ đoạn dưới ngưỡng `min_score` (cấu hình, mặc định tạm 0,25 `[Đề xuất; hiệu chỉnh ở T21]`) | Test với dữ liệu đã biết |
| e | Đa dạng nguồn: nếu một tài liệu chiếm toàn bộ top-k, giữ tối đa `max_per_doc` đoạn (mặc định 4) để tài liệu khác có cơ hội | Test với 2 tài liệu |
| f | Loại bỏ đoạn trùng lặp/chồng lấn gần giống (cùng tài liệu, cùng trang, chồng lấn offset > 50%) | Test |
| g | Đo độ trễ truy hồi (số đo) và bảo đảm dùng chỉ mục HNSW (`EXPLAIN`) | Test + số đo |
| h | Khi không có tài liệu `READY` nào → ném `NoReadyDocumentsException` (T13 ánh xạ `NO_READY_DOCUMENTS`) | Test |

## 4. Đặc tả kỹ thuật

- Cấu hình: `DOCCHAT_RAG_TOP_K`, `DOCCHAT_RAG_MIN_SCORE`, `DOCCHAT_RAG_MAX_PER_DOC` đọc từ môi trường; thay đổi không cần build lại.
- Phạm vi truy vấn là toàn workspace (kế hoạch không có phân quyền theo người dùng ở MVP lõi). **Không** thêm lọc theo người dùng; nếu sau này cần, đặt lọc ngay trong truy vấn SQL.
- Câu hỏi khác ngôn ngữ với tài liệu: phụ thuộc mô hình embedding đa ngôn ngữ (chọn ở T06); kiểm ở T20/T21.

## 5. Tiêu chí hoàn thành
